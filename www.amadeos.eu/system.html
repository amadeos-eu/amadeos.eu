What amadeOS adds to Debian

Debian brings the kernel, the drivers, the X server, systemd and thousands of programs. amadeOS adds the desktop on top: ten packages from the repository amadeos-system, all written in Java.

Debian underneath, amadeOS on top

amadeOS does not replace any part of Debian. Its packages are ordinary Debian packages that use Debian's services: PAM to log in, logind for the session, polkit for administrator rights, NetworkManager, CUPS and apt.

From power-on to the desktop

Display manager

A systemd service starts Xorg and the login screen. It checks the password through PAM in a separate root process, opens a logind session and starts the desktop as the user, in the language, keyboard layout and time zone chosen on the login screen.

Session

Starts the window manager and restarts it if it fails, runs the start-up scripts and your own programs, then the Front Panel. Programs started from the panel each write a log of their own.

Window manager

A floating, reparenting X11 window manager: Motif frames with the CDE window menu, move and resize, minimise to desktop icons, four workspaces, the workspace menu, and the ICCCM and EWMH standards, so programs not written in Java work as well.

Front Panel

Clock, calendar, workspace switch, lock and language buttons, network and updates cells, and drawers that fill themselves from the installed programs' desktop entries and follow every install.

Lock and screen saver

The screen saver uses the X server's idle time, shows a module (Qix, Swarm, Starfield, Floating Logo) and locks the screen. The lock grabs keyboard and mouse and asks for the password through PAM.

Clipboard manager

Keeps a history of what you copied, in memory only, and keeps a copy alive when the program that made it closes. Copies that a password manager marks as secret are left out.

All settings in one place

Settings shows every control in a sidebar with a search field, or, under View > Compact, as CDE's row of buttons with a dialog each. Changes apply at once: the window manager, the panel and every amade application follow the files in ~/.config/amadeos/.

Dialogs of the system

Where the system needs you, it asks in a window of the desktop, in your language and colours.

How Java talks to Linux: JNA

Java cannot speak to the X server or to PAM on its own. amadeOS uses JNA (Java Native Access) for that: Java interfaces that name the C functions of a system library, which JNA calls at run time. There is no C code to compile, so every amadeOS package is the same for every processor (Architecture: all), and the whole binding is readable Java in the module base of amadeos-system.

And where a program does the job better

Not everything needs a native call. amadeOS uses Debian's own tools where they exist: nmcli for the network, xrandr for monitors, xset and xmodmap for keyboard and mouse, timedatectl for the time zone, apt through a small root helper started with pkexec, and IPP spoken directly to CUPS. The handbooks explain each one: Part VII of the User's Handbook and Part VI of the Application Developer's Handbook.
